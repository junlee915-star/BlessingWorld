## 1. 듀오(duo.co.kr) 실측 분석

`m.duo.co.kr` 기준 2026-08-26 실측. (`www.duo.co.kr`은 robots/TLS 문제로 직접 수집 불가,
모바일 도메인으로 대체 수집했다. 컬러·타이포 토큰은 텍스트 추출 방식으로는 확보되지 않았다 →
§6.1 미해결 항목 참조.)

### 1.1 GNB (1뎁스 8개)

듀오소개 · 가입안내 · 고객문의 · 회원&성혼 · 파티&이벤트 · 듀오 유튜브 · 멤버쉽 · 채용정보

관찰: **"무엇인가(소개) → 어떻게 시작하나(가입안내) → 누가 했나(회원&성혼) → 물어보기(고객문의)"**
순서. 상품 설명보다 *절차*와 *증거*를 앞세운다.

### 1.2 메인 섹션 순서 (18개, 상단부터)

1. 결혼정보업계 매출액 1위 (권위 선점)
2. 신상품 런칭 (혜택)
3. "N명이 결혼한 듀오. 이제 당신이 주인공" (숫자 + 2인칭 호명)
4. 듀오 성혼 → 5. 실시간 회원수·성혼수 공개 (검증 가능한 수치)
6~8. 회원 다양성 / 회원 퀄리티 / 전문직·명문대 Pool (동질감 + 안심)
9. 나에게 맞는 서비스 (세그먼트 분기)
10~13. 전문가 기업 / 유튜브 / 2단계 매칭 시스템 / 2:1 매니저 관리 (방법론 설명)
14~18. 언론 노출 / 금감원 전자공시 / 대표브랜드 17년 연속 / 제휴 네트워크 (외부 검증)

관찰: **감정 → 숫자 → 방법론 → 외부 검증**의 4블록 반복. 각 블록 끝마다 동일 CTA가 재등장한다.

### 1.3 신뢰지표 표기 방식

| 지표 | 표기 |
|---|---|
| 회원수 | 35,055명 **(2026.8.24 기준)** — 기준일 병기 |
| 누적 성혼수 | 54,640명 |
| 하루 평균 결혼 | 7명 — 큰 수를 체감 단위로 환산 |
| 6개월 이내 교제율 | 57.3% — 소수점 1자리로 "측정된 값" 인상 |
| 전문직 회원 | 5,811명 / 의료·법조 80% 이상 |
| 수상 | 17년 연속 |

핵심 패턴: **① 기준일 병기 ② 소수점 유지 ③ 큰 수를 하루 단위로 환산 ④ 절대수와 비율 병치.**

### 1.4 가입 절차 = 7단계 서사

서비스 문의 → 1:1 무료상담 → 결혼회원 가입(160여 항목 프로필 + 신원인증서류 4종) →
매칭 상대 찾기 → 만남 → 교제 → 결혼.

관찰: 서류 제출 같은 **부담 단계를 3번째에 배치**하고, 그 앞뒤를 "무료"와 "매칭"으로 감쌌다.
각 단계는 한 문장 설명 + 동사형 제목.

### 1.5 성혼 인터뷰 카드

- 카드 제목 = **커플의 말 인용문** ("우리가 만나지 않았더라면 지금 내 인생이 어땠을지 상상도 안 돼요.")
- 이름은 마스킹 ("곽\*훈, 강\*지"), 회원 유형 배지("멤버스 성혼 커플") 병기
- 필터·탭 없음, "더 보기" 페이지네이션

### 1.6 간편상담신청 폼 (7필드)

지사 선택 → 상담 일정 → 이름 → 성별 → 출생년도 → 최종학력 → 연락처 · 개인정보 동의(필수)/마케팅(선택) · 제출 "신청하기"

관찰: **한 화면 7필드**, 전부 선택형 위주. 자유서술 없음. 상담 *일정*을 앞쪽에 두어 신청을 약속으로 전환한다.

### 1.7 상시 CTA

"간편상담신청" · "문의하기" · "성혼 인터뷰 보기" · "나의 가입비 알아보기"

관찰: 전환 CTA 1개(상담)를 고정하고, 나머지는 **탐색형 CTA**로 부담 없이 다음 페이지로 넘긴다.

## 4. 페이지별 명세

### 4.1 홈 `/` — 듀오식 4블록 재배치

현행 홈(히어로 캐러셀 + IntroTriad + FeatureCardGrid + CTA 밴드)을 유지하되 순서를 재편한다.

1. **히어로** — 3슬라이드 캐러셀 유지. 카피는 감정형 유지, 하단에 CTA 2개(주: 축복상담 신청 / 부: 축복결혼 알아보기)
2. **호명 섹션** (신규) — "N가정이 이 길을 먼저 걸었습니다. 다음은 당신입니다"
   지표 3개를 `.stat-figure`로 병치: 누적 축복가정 수 / 연간 축복식 참여 가정 수 / 사랑의 기술 이수자 수.
   각 수치 아래 `(YYYY.M.D 기준)`을 13px muted로 병기(듀오 §1.3 규칙). 이수자 수는 `course_completions`
   집계로 자동 갱신 가능하나, 앞 두 지표는 협회 제공값이므로 **관리자 화면에서 수기 입력 + 기준일 필수**
   (`site_stats` 테이블, §5.1). 값이 비어 있으면 해당 카드만 렌더하지 않는다.
3. **5축 카드 그리드** — 현행 FeatureCardGrid를 5축과 1:1로 대응시켜 재구성
4. **로드맵 미리보기** (신규) — 7단계 중 앞 3단계만 노출 + "전체 로드맵 보기"
5. **행복의 꽃 미리보기** — 인용문 카드 3개
6. **신뢰 블록** — 무료 상담 / 본인 결정 / 언제든 중단 (현행 TrustBadges 재활용)
7. **하단 CTA 밴드** — 현행 HomeCtaSection 유지
8. **모바일 고정 하단 CTA 바** (신규) — "축복상담 신청" 상시 노출

### 4.2 축복의 씨앗 `/guide` — 가치 전담으로 정리

- 유지: `WhatIsBlessing`, `ValuePillars`(존중·책임·성장·나눔), `TrustBadges`, `FaqAccordion`
- **이동**: `StepJourney` → `/roadmap`으로 이관. 자리에는 "축복로드맵 보기" 배너 CTA만 남긴다.
- 추가: 씨앗 은유를 살린 섹션 헤딩 3단 구성(씨앗 → 뿌리 → 열매)으로 축 간 은유 통일

### 4.3 행복의 꽃 `/stories` — 듀오 인터뷰 카드 형식 이식

- 카드 제목 = **인용문**(현행 `stories` 테이블에 `quote` 컬럼 추가 필요, §5.1)
- 이름 마스킹 유틸 추가 (`김\*수`) — 개인정보 최소화 원칙과도 일치
- 배지: 축복 유형(합동축복 / 축복자녀 / 재축복 등) — 듀오의 "멤버스 성혼 커플" 배지 대응
- 필터: 현행 `/stories`는 `category`(전체/인터뷰/사례/영상) 칩 + 조회수 정렬이 이미 동작한다.
  이를 유지하되 `blessing_type` 배지를 카드에 추가한다(필터 축을 둘로 늘리지 않는다 — 콘텐츠 0건 상태에서 과설계)
- 이름 마스킹은 기존 `family_name` 컬럼을 그대로 쓴다
- "더 보기" 페이지네이션(12건 단위)

### 4.4 사랑의 기술 `/curriculum` — 명칭·서사 변경

- 라벨 전면 교체: 축복가치교육 → **사랑의 기술** (`nav.ts`, `curriculum.ts`, `seo.ts`, admin 라벨, PRD)
- 히어로 카피 재작성: "축복교육 4강좌" → 기술 습득 서사("사랑은 감정이 아니라 배울 수 있는 기술입니다")
- 강좌 카드에 **이수 상태 뱃지**(현행 `course_completions` 활용) + 진도율 바
- 4강 전부 이수 시 `/center/apply`로 가는 **완료 CTA 카드**를 목록 하단에 노출 (듀오식 단계 잠금 해제)
- **강좌 상세 페이지 신설** `/curriculum/:courseId` — 영상 + 강의 요지 + 핵심 정리 + 확인 퀴즈 + 이수 처리.
  목록은 카드 진입점 역할만 한다(SEO상 강좌별 URL 확보, 강좌당 콘텐츠 확장 여지).
- **확인 퀴즈** — 강좌당 3~5문항 객관식. 통과(기본 60%) 시에만 이수 처리되어 진도율에 반영된다.
  문항은 관리자에서 편집(`/admin/curriculum`). 점수는 `course_completions.quiz_score`에 저장한다.
  오답 시 재응시 무제한 — 평가가 아니라 학습 확인이 목적이므로 점수 랭킹·공개는 하지 않는다.

### 4.5 축복로드맵 `/roadmap` — 신규, 8단계

듀오 7단계를 축복 문맥으로 치환하되, 심사와 매칭이 별개 과정이므로 **8단계**로 나눈다.
각 단계: 번호 · 동사형 제목 · 한 문장 설명 · 소요 기간 · 연결 링크.

| 단계 | 제목 | 설명(초안) | 연결 |
|---|---|---|---|
| 1 | 알아보기 | 축복결혼이 어떤 약속인지 편하게 살펴봅니다. | `/guide` |
| 2 | 배우기 | 사랑의 기술 4강좌로 가정의 가치를 익힙니다. | `/curriculum` |
| 3 | 상담 신청하기 | 온라인 신청서를 작성하면 지역가정교회에서 연락드립니다. | `/center/apply` |
| 4 | 상담 받기 | 지역가정교회에서 1:1로 궁금한 점을 나눕니다. | `/center/churches` |
| 5 | 서류 준비하기 | 축복후보자 유형에 맞는 서류를 준비합니다. | `/center/documents` |
| 6 | 심사 | 제출한 서류로 축복후보자 심사를 받습니다. | `/center/documents` |
| 7 | 매칭·약혼 | 상대를 소개받고 서로의 뜻을 확인합니다. | — |
| 8 | 축복식 | 축복결혼식에 참여하고 새 가정을 시작합니다. | — |

- 부담 단계(서류)를 5번째에 두고 앞뒤를 "상담"과 "심사"로 감싼 것은 듀오 §1.4 배치를 따른 것.
- 7단계(매칭·약혼)는 사용자가 스스로 진행할 수 없는 유일한 단계다. 카드에 "기다리는 시간"에 대한
  안내 문구를 두어 이탈이 아니라 대기임을 명확히 한다(듀오 6단계 '교제'의 역할).
- 각 단계 카드에 **"지금 여기"** 표시 — 로그인 사용자는 `blessing_progress` 테이블 값으로 자동 하이라이트.
- 하단에 **축복 준비도 진단** 위젯(듀오 "가입비 계산" 치환): 유형 선택 → `documents.ts` 체크리스트에서
  준비 완료 항목 체크 → "N/12 준비됨" + 미비 서류 안내. 클라이언트 계산, 서버 저장 없음.
- 6·7단계는 협회 확정 정보 필요 → §6.1.

### 4.6 축복센터 `/center` — 신규 허브 + 3개 하위

허브 화면 구성: 3개 진입 카드(신청 / 교회찾기 / 서류) + 상담 안내(무료·비강제·중단 가능) + 문의 전화.

- `/center/apply` — 현행 `/onboarding` 5단계 위저드 이전.
  듀오식 1화면 폼과의 절충: **1단계로 "핵심 7필드"를 받아 즉시 제출 가능**하게 하고,
  나머지 상세(교육 이수 여부, 희망 상담 방식 등)는 제출 후 선택 입력으로 돌린다.
  → 이탈 지점이 5단계에 분산되던 것을 1단계로 모은다. 기존 `guidance_requests` 스키마 호환 유지.
  듀오와 달리 **상담 일정 예약은 넣지 않는다**(지역가정교회 일정이 중앙 관리되지 않음).
  대신 **상담 방식 선택 필드**를 둔다: 교회 방문 / 전화 / 화상 — 라디오 3개, 필수.
  핵심 7필드 = 이름 · 연락처 · 성별 · 출생연도 · 거주 지역(교회 매칭용) · 축복후보자 유형 · 상담 방식.
- `/center/churches` — 현행 유지, 경로만 변경. 지도/지역 필터 그대로.
- `/center/documents` — 현행 유지, 경로만 변경. 로드맵 5단계에서의 진입 동선 추가.

### 4.7 축복관리자 `/admin/*`

- 브랜딩만 "축복관리자"로 통일(`AdminHeader`), 기존 6개 화면 유지
- 사이드 내비를 6축 순서로 재정렬: 스토리 / 강좌 / 로드맵 / 신청 / 교회 / FAQ / 회원
- **신규 화면 1개**: 로드맵 단계 콘텐츠 관리(`/admin/roadmap`) — 단계별 제목·설명·소요기간 편집
- 신청 관리에 **단계 상태 변경** 기능 추가(신청→상담완료→서류접수→심사→축복식) — `blessing_progress` 연동
- 대시보드(신규, 선택): 축별 카운트 + 최근 신청 5건. 홈 수치 섹션(§4.1-2)의 원천 데이터와 동일 쿼리 사용

## 5. 데이터·디자인 변경사항

### 5.1 Supabase 마이그레이션 (신규 `0012_six_pillars.sql`)

```sql
alter table stories add column if not exists quote text;          -- 인용문 제목
alter table stories add column if not exists blessing_type text;  -- 배지
create table if not exists roadmap_steps (...);                   -- 관리자 편집용 7단계

-- ⚠ 실측 확인 사항: blessing_progress.step_key 의 CHECK 제약이 step_01~step_06(6단계)로
-- 고정되어 있다. 로드맵이 7단계이므로 제약을 교체해야 한다.
alter table blessing_progress drop constraint blessing_progress_step_key_check;
alter table blessing_progress add constraint blessing_progress_step_key_check
  check (step_key in ('step_01','step_02','step_03','step_04',
                      'step_05','step_06','step_07','step_08'));

-- 사랑의 기술 확인 퀴즈
alter table courses add column if not exists quiz jsonb;              -- [{q, choices[], answer}]
alter table courses add column if not exists pass_score int default 60;
alter table course_completions add column if not exists quiz_score int;

-- 홈 수치 섹션 (협회 제공값 + 기준일)
create table if not exists site_stats (
  key text primary key,        -- 'blessed_families' | 'yearly_ceremony_families' | ...
  label text not null,
  value bigint,
  basis_date date,             -- 기준일. null이면 카드 미노출
  display_order int not null default 0
);
-- + 관리자 쓰기 RLS 정책 추가(현재 정책은 본인 행 읽기 위주)
-- guidance_requests: 상담 방식 컬럼
alter table guidance_requests add column if not exists consult_method text
  check (consult_method in ('visit','phone','video'));
```

`stories.category`도 `check (category in ('interview','case','video'))`로 고정되어 있다.
축복 유형 배지는 이 컬럼을 재사용하지 않고 **새 `blessing_type` 컬럼**으로 분리한다
(카테고리=콘텐츠 형식, 배지=축복 유형으로 의미가 다르다).

### 6.2 남은 콘텐츠 리스크

- **수치 3종의 실제 값과 기준일**: 구조(`site_stats`)는 준비하되 값은 협회에서 받아 입력해야 한다.

### 설계와 달라진 점

1. **신청서 5단계 위저드 → 한 화면 7필드**로 실제 교체했습니다. 이에 따라 스텝 인디케이터·
   beforeunload 이탈 방지·스텝별 자동 포커스가 사라졌고, 대신 제출 시 첫 오류 필드로
   스크롤·안내합니다. sessionStorage 임시 저장은 유지하며, 개편 이전의 `{step, form}` 형태
   초안도 읽어서 복원합니다.
2. **홈의 "행복의 꽃 미리보기" 섹션은 넣지 않았습니다.** 스토리 콘텐츠가 0건이라 빈 섹션이
   되기 때문입니다. 5축 카드에는 이미 행복의 꽃 진입점이 있습니다. 인터뷰가 확보되면 추가하세요.
3. **로드맵 단계 지정은 로그인 신청 건에만 가능합니다.** `blessing_progress`가 `user_id`를
   요구하는데 비로그인 신청은 계정이 없어서입니다. 신청 관리 화면에서 해당 행은
   "비로그인 신청(단계 기록 불가)"로 표시됩니다. 전원에게 단계를 기록하려면 신청 시
   계정 생성을 요구하거나, `guidance_requests.id` 기준의 별도 진행 테이블이 필요합니다.
4. **`site_stats.value`는 비워둔 채 배포됩니다.** 마이그레이션은 지표 3종의 '자리'만 만들고
   값·기준일은 넣지 않습니다. 둘 중 하나라도 비면 홈에서 그 카드가 렌더되지 않으므로,
   협회 확정치를 `/admin/stats`에서 입력하기 전까지 홈 수치 섹션 자체가 나타나지 않습니다.

### 배포 전 반드시 할 일

3. `/admin/curriculum`에서 강좌별 확인 퀴즈 문항 등록 (미등록 시 '다 들었어요' 폴백)
